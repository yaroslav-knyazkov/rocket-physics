Задача: адаптировать установленный набор агентов под этот репозиторий. Ничего не выдумывать — только то, что подтверждается файлами проекта или ответом пользователя.

## 0. Слияние с уже существовавшими файлами (если есть)

- Есть `CLAUDE.kit.md` (установщик не стал трогать старый `CLAUDE.md`) — предложи план слияния: основа — `CLAUDE.kit.md`, правила и факты из старого `CLAUDE.md`, которых в наборе нет, переносятся в новый раздел «Особенности проекта» в конце; конфликтующие правила — показать пользователю, выбирает он. После «да» — записать результат в `CLAUDE.md` и удалить `CLAUDE.kit.md`.
- Есть `.claude/settings.kit.json` — слить в `.claude/settings.json`: добавить ключи `agent`, `extraKnownMarketplaces`, `enabledPlugins` и хуки набора, сохранив все существующие хуки и `permissions` проекта. Показать дифф, записать после «да», удалить `settings.kit.json`.

## 1. Разведка (только чтение)

Собери факты, не читая большие файлы целиком:

- Манифесты и точки входа: `package.json` (scripts, workspaces), `pyproject.toml`/`requirements*.txt`/`setup.cfg`, `go.mod`, `Cargo.toml`, `pom.xml`/`build.gradle`, `Makefile`, `docker-compose*.yml`, `Dockerfile`, `.env.example`, конфиги тест-раннеров (`pytest.ini`, `vitest.config.*`, `jest.config.*`, `conftest.py`).
- Где код backend/ядра и frontend (каталоги верхнего уровня, монорепо-пакеты).
- Команды: запуск, тесты (точечный прогон одного файла + полный прогон), сборка frontend. Проверь, нет ли ловушек: `npm test` = watch-режим (`"test": "vitest"` без `run`), обязательные env-префиксы, маркеры медленных/интеграционных тестов, лимит воркеров.
- Порты по умолчанию (из конфигов/скриптов), наличие Postgres/Redis (`DATABASE_URL`, `REDIS_URL` в `.env.example`).
- Платные/внешние API (ключи в `.env.example`, SDK в зависимостях: openai, anthropic, stripe, twilio, resend, …).
- Тип деплоя (Dockerfile/CI/хостинг-конфиги) или «локальный/библиотека».
- `git remote -v` — есть ли `origin` (нужен для worktree-режима).

Если репозиторий пустой (greenfield) — заполни только то, что известно, остальное оставь `TODO: определит architect` и переходи к шагу 3.

## 2. Черновик профиля → подтверждение

Покажи пользователю таблицу «Профиль проекта» с найденными значениями и источником каждого (файл:строка). Спроси через `AskUserQuestion`:
- верно ли (с вариантами «да» / «поправлю»),
- включать ли worktree-режим (рекомендуй «да», только если есть `origin` и проект — git; иначе «нет»),
- язык общения (по умолчанию русский).

## 3. Запись (после «да»)

1. `CLAUDE.md` § «Профиль проекта» — заменить все `{{...}}`/`TODO` подтверждёнными значениями; ловушки окружения — списком под таблицей. Название и описание проекта в шапке — если ещё плейсхолдеры, спроси.
2. Worktree-режим включён → создай `.claude/wt.config.json` по образцу `.claude/wt.config.example.json`: `env_file`, `venv_dir`, `local_artifacts` (node_modules/.venv/.env по реальным путям), `backend_port_base`/`frontend_port_base`, `worktree_root` (вне облачных папок, если проект лежит в OneDrive/Яндекс.Диске/Dropbox).
3. Агенты — правки только там, где проекту реально нужно отличаться от универсального поведения:
   - `security.md` § «What you audit» — дописать 2-5 строк о реальной поверхности атаки (конкретные платные API, точки входа);
   - `frontend-developer.md` — если frontend нет вовсе, сообщи пользователю, что агент можно исключить на kickoff (сам файл не удалять);
   - модели агентов (`model:` во frontmatter) не менять без явной просьбы.
4. Трекер: если `dev/status.json`/`dev/PROJECT-STATUS.md`/`dev/journal.md` отсутствуют — создать из `.claude/templates/` с подстановкой `{{PROJECT_NAME}}`, `{{PROJECT_DESCRIPTION}}`, `{{TODAY}}`.
5. Если в корне есть `.gitignore` и в нём нет строк из блока `# --- agents kit` — предложи их добавить (список — в README набора агентов), добавляй только после «да».
